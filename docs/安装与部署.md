# 安装与部署

本文档说明 MetroRail 的环境要求、安装、升级、卸载与常见故障排查。

---

## 1. 环境要求

| 项目 | 要求 | 说明 |
| :-- | :-- | :-- |
| 服务端 | Spigot / Paper **1.18 及以上** | 编译基线为 Spigot API 1.18.2，`api-version: '1.18'`；Paper 现代版本可直接运行 |
| Java | **17+** | 插件以 `--release 17` 编译 |
| Metro | **必需** | `plugin.yml` 中是 `depend: [Metro]`，缺少 Metro 时本插件不会加载 |

> MetroRail 只用到 Bukkit 公开 API（矿车是普通 `Minecart` 实体），**不涉及 NMS**，因此跨版本升级通常无需改代码。

---

## 2. 安装步骤

1. 从 Release 或自行构建得到 `MetroRail-1.0.0.jar`。
2. 关闭服务器（或确认可在热载后整服重启）。
3. 把 jar 放入服务器根目录的 `plugins/`。
4. 确认 `plugins/Metro/` 已存在（Metro 插件必须是启用状态）。
5. 启动服务器。控制台应出现类似日志：

   ```
   [MetroRail] MetroRail 已启用（Metro 对接：可用，车型 2 种，轨道 0 节点，道岔 0 处）
   ```

   其中「Metro 对接」若显示 **未找到**，说明 Metro 未加载或版本不匹配，请先解决 Metro 的问题。

6. 首次启动会自动生成 `plugins/MetroRail/` 目录及 `config.yml`、`vehicles/`、`lang/`、`web/` 等。
7. 进游戏执行 `/mr help`，能看到帮助列表即安装成功。

---

## 3. 目录结构

```
plugins/MetroRail/
├── config.yml               # 主配置
├── lang/                    # 语言文件
│   ├── zh_CN.yml
│   └── en_US.yml
├── vehicles/                # 车型物理参数
│   ├── default.yml
│   └── express.yml
├── web/                     # 调度网页静态资源（首次从 jar 释放）
│   ├── index.html
│   ├── style.css
│   └── app.js
├── graph.yml                # 轨道图（运行时生成）
├── switches.yml             # 道岔登记
├── balises.yml              # 应答器登记
├── occupancy.yml            # 占用账本
├── rail-trains.yml          # 列车属性 / 模板
├── trains.yml               # 编组
└── mileage.yml              # 里程记录
```

---

## 4. 升级

1. 停止服务器（或热载前先确认插件已完全卸载）。
2. **删除旧的 `MetroRail-*.jar`**。
3. 放入新版本 jar。
4. 重启服务器。

> **注意**：`config.yml` 不会被覆盖更新。新版本新增的配置项会以「缺失即用内置默认值」的方式读取，
> 但**不会自动写入**到旧文件里，需要手动补上（或删除 `config.yml` 后重启重新生成）。
>
> `lang/*.yml`、`vehicles/*.yml`、`web/*.js` 同理 —— 已经存在于磁盘上的文件不会被 jar 覆盖。

> **热载**：若使用 PlugMan 之类的热载工具。`/mr reload` 只重载 MetroRail 自己的配置与数据，
> 由于调度网页会占用端口，热载可能留下旧实例占着端口，**推荐整服重启**。

---

## 5. 卸载

1. 停止服务器。
2. 删除 `plugins/MetroRail-*.jar`。
3. 按需删除 `plugins/MetroRail/`（保留则下次装回可沿用全部数据）。

---

## 6. 故障排查

| 现象 | 原因与处理 |
| :-- | :-- |
| 插件根本没加载 | 没装 Metro，或 Metro 加载失败。看控制台 `Unknown dependency Metro`。 |
| `/mr` 无输出 | 命令未注册。检查是否有插件冲突占用 `mr` / `metrorail` / `mrail` 别名。 |
| 启动日志「Metro 对接：未找到」 | 运行时可用了 Metro 的类，但 API 反射失败。确认 Metro 是受支持版本，并用 `/mr status` 查看。 |
| `/mr drive` 提示「附近没有可接管的矿车」 | 站在矿车旁（默认 8 格内），或调大 `drive.scan-radius`。 |
| 接管后速度没变化 | `drive.tick-interval` 过大；或该矿车被别的插件（如原版动力铁轨逻辑）覆盖。 |
| 调度网页打不开 | `web.enabled` 为 false，或端口被占用（插件会自动尝试 `port+1`~`port+10`，看日志里的实际端口）。 |
| 重启后道岔 / 应答器丢失 | 相关数据在 `switches.yml` / `balises.yml`；确认数据目录有写权限。 |
| 语言不对 | `config.yml` 的 `language`，或玩家用 `/mr lang <locale>` 单独切换。 |

排障常用命令：`/mr status`（驾驶 / Metro 对接 / 车型与编组统计）、`/mr graph status`（图与设施统计）。

---

## 7. 备份建议

需要备份的只有 `plugins/MetroRail/` 整个目录，尤其是：

- `graph.yml`、`switches.yml`、`balises.yml`（基础设施登记，重建成本高）
- `rail-trains.yml`、`trains.yml`（列车属性与编组）
- `config.yml`、`vehicles/`（自定义参数）

`occupancy.yml`、`mileage.yml` 属于运行态数据，丢失影响不大。
