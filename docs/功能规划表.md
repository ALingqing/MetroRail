# Metro 铁路运行附属 · 功能规划表（开工前评审版）

> 目标：以 **Skyworld-Railway（SkyRail Suite：STF / STCS / STA / SkyPCC）** 的全部功能与附属为参照，
> 把 **Metro（CubeX-MC/Metro，`/m`）目前没有的能力** 做成一个独立附属插件，与 Metro 并存运行。
>
> 本文档是「开工前请你看一眼」的功能清单，**尚未写代码**。请你先审阅/增删/排序，确认后我再动手。
>
> 暂定附属名：**MetroRail Suite（MRS）**，主命令暂定 `/mr`（可改）。

---

## 0. 两个项目的定位差异（为什么需要附属）

| 项目 | 定位 | 核心能力 | 缺口 |
| :-- | :-- | :-- | :-- |
| **Metro** | 「服务器里的交通基础设施」 | 多线路网络、停靠区、换乘、票价、GUI、矿车传送门、网页地图、经济、权限 | 只有「自动发车 + 右键乘车」，**没有手动驾驶、没有列控、没有调度台、没有信号/道岔/占用/M A** |
| **SkyRail Suite** | 「可交互的铁路运行 / 列控仿真」 | 手动驾驶级位、车型物理、编组、道岔、RailGraph、里程、占用/预约、影子 MA/EoA、强制保护、车载 HMI、自动牌子、网页调度（PCC）、事件日志、完整性监测 | 它本身不做「线网/票价/换乘/GUI」那套运营层 |

**结论：Metro 管「运营 / 线网 / 玩家侧乘客体验」，SkyRail 管「驾驶 / 列控 / 调度」。附属负责把后者的能力补进 Metro —— 即 `Metro = 线网运营层` + `附属 = 铁路运行/列控层`。**

## 3. 技术架构与依赖（初步）

```
Minecraft 玩家 / Metro 矿车 / 铁轨 / 红石
                  │
          ┌───────┴────────┐
          │  Metro（运营层）│  ← 已有：线网/停靠区/换乘/票价/GUI/传送门
          └───────┬────────┘
                  │  MetroAPI（org.cubexmc.metro.api）
          ┌───────┴────────┐
          │ MetroRail 附属  │
          │ ┌────────────┐ │
          │ │ 运动/驾驶   │ │  （对应 STF）
          │ │ 图/定位/占用│ │  （对应 STCS）
          │ │ 网页调度    │ │  （对应 SkyPCC，附属自带轻量 HTTP/SSE）
          │ └────────────┘ │
          └────────────────┘
```

- **依赖**：`depend: [Metro]`（或软依赖 + 运行时检测）；通过 `MetroAPI.getInstance()` 读取线路/停靠区/门票；不下发票价时只做运行层。
- **对接点**：优先用 Metro 的 **公开 API**（`docs/api.md`：线路、停靠区、传送门、所有权、票价、`checkCanBoard`、快照）。
- **可能需要的底层**：矿车速度/物理控制在 Bukkit 层很难做（SkyRail 用了 NMS 显示适配 + TrainCarts 式牌子），附属需要评估：
  - 方案一（推荐先做）：**只做「可观测 + 可交互」部分**（HMI、牌子、图、占用、网页、命令），运动/驾驶用 Bukkit 可见手段（速度向量、拉杆、动力铁轨）。

## 5. 需要你拍板的问题

1. **附属名称/命令前缀**：`MetroRail Suite` + `/mr`？还是别的？
