# 列控与信号

本篇讲 MetroRail 的「铁路运行层」：**轨道图 → 定位 → 占用 → 行车许可 → 列控模式**，
外加道岔、应答器与完整性监测。

> 设计参照 SkyRail 的 STCS 模块，命令收敛到 `/mr`。
> 默认一切**只读**（影子模式），需要显式切换才会施加制动。

---

## 1. 轨道图 RailGraph

轨道图是「有向图」：节点是轨道方块，边是有向连接（含坡道），每条边有长度。

### 建图

站在线路起点（或任意位置），用管理员权限执行：

```
/mr graph rebuild
```

插件会从你所在位置出发，沿四个水平方向与坡道**洪泛**展开，节点上限由 `rail.max-graph-nodes` 控制（默认 20000）。
结果持久化到 `plugins/MetroRail/graph.yml`。

### 查看

```
/mr graph status
```

```
[MetroRail] 轨道图：world，节点 1284，边 3902，占用 0，道岔 3，应答器 8
```

| 命令 | 说明 |
| :-- | :-- |
| `/mr graph status` / `/mr graph inspect` | 图统计 |
| `/mr graph rebuild` | 重建（需 `metrorail.admin`） |
| `/mr graph export` | 把全部节点 id 打到控制台日志（需 `metrorail.admin`，用于外部工具解析） |

> **提示**：图是「快照」。大规模改动线路后应重新 `rebuild`，否则新铺的轨道不在图里。

## 2. 道岔

「道岔」由**一组相邻铁轨 + 一个控制点（拉杆）**构成。

### 登记

站在拉杆附近：

```
/mr switch scan west_points
```

扫描半径 `drive.scan-radius`（默认 8 格）。登记后写入 `switches.yml`。

### 查看与转换

```
/mr switch list
/mr switch info <名字>
/mr switch set <名字>        # 也可以 /mr switch toggle <名字>
/mr switch remove <名字>
```

### 现场操作（无需命令）

手持 **红石火把**（「道岔棒」）**右键已登记的拉杆**即可转换。
若该拉杆尚未登记，会提示你先 `/mr switch scan <name>`。

> 转换需要 `metrorail.switch` 权限（默认 OP）。

## 3. 应答器（balise）

应答器就是**告示牌**。放置或修改告示牌时，第 1 行写标记 `[xxx]`，第 2 行起写数据，
插件会自动登记（写入 `balises.yml`），拆掉牌子自动注销。

支持 5 种标记：`station` / `property` / `spawn` / `limit` / `stop`。
详细写法见 [自动牌子.md](自动牌子.md)。

### 查看

```
/mr balise                 # 全部
/mr balise station         # 只看车站牌
/mr origin                 # 等价 /mr balise spawn
/mr end                    # 等价 /mr balise stop
```

## 4. 占用账本 OccupancyLedger

占用以**有向边的 id**为粒度，记录「谁持有这一段」。两种持有语义：

| 方式 | 语义 | 用途 |
| :-- | :-- | :-- |
| `occupy`（独占） | 同一时刻只允许**一列车**持有 | 正常进路占用 |
| `hold`（共享） | 多列车可同时持有 | 站台 / 进路预留 |

要点：

- **证据保留**：列车卸载、玩家离开，占用**不会**自动出清 —— 必须显式释放（`/mr ma release` 或会话结束）。
- **持久化**：写入 `occupancy.yml`。
- `isBlockedFor(edge, holder)` 会**忽略自己**持有的段，所以自己的预约不会挡住自己。

## 5. 行车许可 MA / 授权终点 EoA

MA 的计算方式是「沿前进方向逐段推进，取最先遇到的障碍」：

```
从当前节点开始
  ├─ 无匹配出边（断头）        → reason = end-of-track
  ├─ 下一段被他人占用          → reason = occupied        ← 真正会让 MA 停住
  ├─ 累计距离 ≥ 探测上限        → reason = max-lookahead
  └─ 没有轨道图                → reason = no-graph
```

沿途还会收集应答器上的**限速**，取最低值作为 `limitSpeed`。

| 参数 | 配置键 | 默认 |
| :-- | :-- | :-- |
| 最大探测距离 | `rail.ma-lookahead` | 256 格 |

### 命令

```
/mr ma status            # 剩余 MA(m)、原因、段数
/mr ma demand [段数]     # 向前预约 N 段（默认 3）
/mr ma release           # 释放本车全部占用
/mr ma ack               # 确认告警
```

`/mr status` 里也会显示一行：`列控：模式 shadow，状态 FS，MA 142.30m（max-lookahead）`。

## 6. 列控模式 ControlMode

| 模式 | 行为 | 适用 |
| :-- | :-- | :-- |
| `shadow` | 只读计算并**显示** MA，**不施制动** | 默认；先观察，建立信任 |
| `bypass` | 完全忽略 MA（连算都不算） | 调试 / 特殊作业 |
| `isolate` | 不计算 MA，纯手动 | 故障车、调车 |
| `enforce` | MA 触发时**强制紧急制动** | 实验性 ATP，需 `metrorail.admin` |

切换：

```
/mr mode shadow
/mr mode enforce
```

> **强烈建议**：正式使用前先跑一段时间的 `shadow`，用 `/mr ma status` 核对 MA 距离是否与肉眼判断一致，
> 再考虑打开 `enforce`。`enforce` 会真的拉紧急制动。

## 7. 列车状态机 TrainState

驾驶会话有一个状态，反映当前处于哪种制动 / 保护情形：

| 状态 | 含义 |
| :-- | :-- |
| `SB` | 常用制动 Service Brake |
| `FS` | 全常用制动 Full Service |
| `SH` | 调车 Shunt |
| `SR` | 信号恢复 Signal Reset |
| `TR` | 紧急制动 Trip |
| `PT` | 防护 Protection（`enforce` 通道触发） |

状态会显示在 `/mr status` 与计分板上。站停牌、强制停车牌都会改变它。

## 8. 完整性监测 TIMS

TIMS 会持续采样编组内每节车厢的位置，并校验：

1. **车厢是否齐全** —— 编组登记了 N 节，就必须都能找到。
2. **采样时效** —— 每节车厢必须在 `rail.tims-timeout-ticks`（默认 40 tick）内被观测到。
3. **相邻车厢间距** —— 不得超过 `rail.tims-max-spacing`（默认 8 格，0 = 不检查）。

结果在 `/mr status` 的「完整性」行显示（`正常` / `异常` + 原因）。

## 9. 事件日志 EventLog

驾驶权取得 / 释放、道岔转换、MA 申请、模式切换、图重建、应答器登记等都会写入事件日志，
并在 [调度网页](调度网页.md) 的 `events` 栏与 `/api/events` 接口中展示。

## 10. 一个推荐的落地顺序

1. `/mr graph rebuild` 建图（在主线起点处）。
2. 沿途放 `[station]` / `[stop]` / `[limit]` 牌子，登记车站与限速。
3. 在岔区 `/mr switch scan <name>` 登记道岔，用红石火把现场试转。
4. `/mr mode shadow`，开一段车，用 `/mr ma status` 观察 MA 是否符合直觉。
5. 用 `/mr ma demand 3` 试着预约前方进路，另一列车跑过来时看 MA 是否收短。
6. 一切正常后再考虑 `enforce`。
